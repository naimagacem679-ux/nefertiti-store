# حالات الطلب وقاعدة المخزون

**القاعدة الأساسية:** فتح واتساب لا يخصم شيئاً، وإنشاء الطلب لا يخصم شيئاً. المخزون يُخصم مرة واحدة فقط، عندما تنقلين الطلب إلى «مؤكَّد».

| الحالة | المعنى | المخزون |
|---|---|---|
| `new` جديد | وصل الطلب من الزبون (سُجِّل في D1 ثم فُتح واتساب) | لا يتغير |
| `no_answer` لا يرد | حاولتِ الاتصال ولم يرد | لا يتغير |
| `confirmed` مؤكَّد | اتفقتِ مع الزبون | **يُخصم الآن مرة واحدة** |
| `shipped` شُحن | خرج مع شركة التوصيل | بلا تغيير |
| `delivered` سُلِّم | استلمه الزبون | بلا تغيير |
| `cancelled` ملغى | ألغي الطلب | يُعاد المخزون إن كان قد خُصم |
| `returned` مرتجع | رجع بعد الشحن أو التسليم | يُعاد المخزون |

## الانتقالات المسموحة فقط
`new` ← `confirmed` / `cancelled` / `no_answer` · `no_answer` ← `confirmed` / `cancelled` · `confirmed` ← `shipped` / `cancelled` · `shipped` ← `delivered` / `returned` · `delivered` ← `returned`. الملغى والمرتجع نهائيان. أي انتقال آخر يُرفض.

## ضمانات
- التأكيد والخصم يجريان في **معاملة واحدة** (D1 batch). إن كان أحد المنتجات غير متوفر بالكمية، يفشل الخصم (قيد `CHECK stock >= 0`) ويُلغى كل شيء، فيبقى الطلب كما هو.
- العلم `stock_committed` يمنع الخصم المزدوج لو ضُغط «تأكيد» مرتين.
- كل تغيير حالة يُسجَّل في `order_status_log`، وكل تغيير مخزون في `stock_movements` (مع من فعله).
- أسعار الطلب تُحسب على الخادم من قاعدة البيانات، وتُحفظ نسخة منها (اسم المنتج والسعر) في `order_items` فلا تتأثر بتعديل المنتج لاحقاً.
- الخصم يشمل مخزون المقاس/اللون (`product_variants`) أو مخزون المنتج حسب ما اشتراه الزبون.

هذه القواعد مُنفَّذة ومُختبرة فعلاً في `scripts/test_order_flow.py` على نفس مخطط القاعدة (15 اختباراً ناجحاً). وظائف المرحلة الثانية ستنفذ نفس الـ SQL.
